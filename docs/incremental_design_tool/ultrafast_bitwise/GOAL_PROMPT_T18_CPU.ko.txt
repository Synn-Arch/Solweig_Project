/goal AlanSynn/solweig-project의 ultrafast incremental engine에서 CPU 수용 목표 미달분에 대해, 원본 문서(DESIGN.ko.md, TASKS.ko.md, acceptance_targets.yaml)에 이미 명시된 수단만 사용해 목표치 도달 가능 여부를 측정으로 검증하라. 새로운 최적화 아이디어를 도입하지 마라 — TASKS.ko.md T17 카드가 나열한 후보와 DESIGN이 정한 순서·조건을 그대로 실행하고, 각 후보가 목표에 얼마나 접근시키는지 measured ablation으로 판정하여 목표별 도달 가능/불가 판정을 내려라. 고정 full-domain oracle(pinned worktree solweig_oracle_e0d19fc)에 대한 raw-bit parity와 기존 의미 보존은 전제이며, 위반한 개선은 측정값으로도 인정하지 않는다.

필수 문서와 현재 상태
- README.ko.md, DESIGN.ko.md, TASKS.ko.md(특히 T17 카드), acceptance_targets.yaml, WORKLOG_ULTRAFAST.md, benchmarks/ultrafast/t16_cpu_lane.py를 먼저 읽어라.
- 검증 출발점(기록된 현재 상태, main 1b3888c 기준): cpu_selected_exact 33,746.6ms p95, cpu_full_day_local 21,397ms cold·20,131ms warm, cpu_full_recompute_warm 19,384ms, steady RSS 286.9MiB. 병목 귀속(T16 기록): selected-exact solve = svf march 16.9s + time loop 16.4s, full-day는 fused kernel 96%. DESIGN §35 W1 대비 참고: 원본 네이티브 SVF ~20s·time loop ~17s — 이 두 성분은 현재까지 거의 개선되지 않았다(개선은 다른 성분에서 나옴). E2E에는 coalescing 대기가 포함된다(yaml include_queue_epoch_wait, jobs.py coalescing_window_ms 기본 500ms — T16 queue_wait 0.511s). 이 수치를 baseline으로 삼되, 캠페인 첫 단계에서 동일 조건 재측정으로 재확인하라.
- 4-core pinned 권위 판정(acceptance_targets.yaml primary_cpu_policy)은 macOS dev host에서 affinity 고정이 불가하여 BLOCKED 상태다. 참조 호스트가 제공되면 최종 판정을 그 호스트에서 내리고, 아니면 provisional 표기를 유지한다. 이것은 도달 가능성 판정의 조건이지 목표 완화가 아니다.
- GPU 항목(20-시나리오 메모리, legacy cube-scope 핀)은 본 캠페인에서 제외한다. CPU 잔여만 다룬다.

변경 불가능한 정확성 계약 (GOAL_PROMPT.ko.txt 1~8 승계)
- 원본 8계약 전부: raw-bit 비교(signed zero·NaN payload), profile 분리, oracle worktree 분리, 6° sky floor·read reach·계수·연산 순서·정밀도 보존, fastmath/unordered reduction/FMA/Horner 금지, shadow previous-state while·last overshoot·R4/R6 보존, thermal checkpoint 오재사용 금지, accepted operation 손실 금지.
- T17 카드 단서를 그대로 적용: "성능 목표 미달을 핑계로 proof 없는 상태 재사용을 넣지 않는다", 채택 관문은 "기본 fallback보다 느리거나 memory 목표를 깨면 채택하지 않는다", 실패한 후보와 이유도 남긴다.

검증 대상(acceptance_targets.yaml final 목표 — 느슨하게 하지 마라)
- cpu_selected_exact p95 ≤100ms / cpu_full_day_local p95 ≤3,000ms / cpu_full_recompute_warm p95 ≤15,000ms / steady RSS ≤256MiB. 각 목표에 대해 최종 판정은 "도달(측정 근거)" 또는 "문서 내 수단으로는 미도달(잔여 exclusive-time 귀속과 함께 불가 근거)" 둘 중 하나다.

작업 카드 — 전부 원본 문서에 명시된 수단만 (T18–T23 = TASKS T17 카드 후보 4종 + 문서가 정한 선행조건; T24–T28 = DESIGN이 별도 명시한 잔여 후보 — §710 scheduling task, T10이 연기한 §571/§579 migration, T16 종료 기록이 명명한 §474, §809 연구 후보, §716/§801 경미 후보)
- T18 — 기본 full canonical fold 최적화. DESIGN §807: "기본 full canonical fold를 먼저 최적화한 뒤 별도 ablation으로 판단한다", §589: equality-triggered는 "기본 sparse/fusion보다" 낮은 우선순위 — 문서가 정한 선행 조건이므로 첫 카드. 수단은 정확성 보존 하의 구조 개선(임시 배열 제거, arena 재사용 §601, layout·dead scan 제거)으로 한정하고 연산 순서 동치를 논증한다. 측정: full-day·recompute-warm 접근 폭.
- T19 — cache-aware ray-state reuse. T17 카드 후보 + DESIGN §352: angle/scale/logical shape별 potential step sequence + amplitude별 정확한 prefix length 선택. 단 "기존 while의 previous-state semantics와 first-step exception을 그대로 반영" 조건과 "단순 dz<=amplitude mask는 대체 명세가 아니다" 단서를 그대로 지킨다. 측정: selected-exact 접근 폭.
- T20 — equality-triggered temporal convergence. T17 카드 후보 + DESIGN §589: dirty recurrence에서 reference future inputs 동일 + carried state(6 planes·4 scalar) 전 비트 동일일 때만 suffix 재사용, 부분 equality·작은 온도차로 조기 종료 금지. T18 이후 착수(§589 우선순위 규정).
- T21 — prefix-accumulator suffix fold ablation. T17 카드 후보 + DESIGN §807: exact accumulator prefix 저장 후 그 지점부터 suffix fold 재실행(old를 빼는 방식 아님). 10 accumulator 다중 prefix checkpoint의 memory cost를 정량화하고 목표 미달·느림이면 폐기·기록한다.
- T22 — 2-bit extended vbsh encoding + 더 넓은 regime proof. T17 카드 후보 + DESIGN §432/§842(vbsh=2.0 counterexample이 1-bit binary state 전제를 차단하는 R6/R7 맥락). state 표현 압축이 어느 목표에 얼마나 기여하는지 ablation으로 판정하고, 기여가 없으면 그 사실을 기록한다.
- T23 — steady RSS 256MiB + DESIGN §12.4 AOT 전환 기준 적용. §12.4 트리거 1호("JIT compiler/runtime residency가 lightweight target을 막는다")가 286.9>256MiB로 발화했는지 재평가하고, 발화 시 B6/§26/§173의 cpu-native(C++ AOT) 비교를 같은 ABI/trace/fixture로 수행한다. §173 회계 범위(resident mmap·scratch·checkpoint·threads·code)로 측정한다. Numba 유지 근거 또는 전환 필요 근거 둘 다 정직하게 남긴다.
- T24 — adaptive epoch/debounce scheduling (DESIGN §710 "별도 scheduling task로 평가"). §710 경고가 그대로 적용된다: "Compute target이 100ms인데 대기 자체가 100ms이면 target에 도달할 수 없다" — 현재 coalescing 대기 500ms는 그 자체로 cpu_selected_exact 100ms 목표를 초과하므로, 이 카드 없이는 selected-exact 도달 판정 자체가 성립하지 않는다. window 축소(또는 편집 특성 adaptive)를 reducer determinism·idempotency·conflict resolution 불변 조건 아래에서 평가하고, 실제 대기 감소를 selected-exact E2E ablation으로 측정한다. §710 단서: 빠른 visual movement를 exact scientific publication으로 오인시키지 않는다.
- T25 — spatial/COW checkpoint 확장 (DESIGN §571·§579, TASKS T10이 "별도 schema migration과 test"로 명시적으로 연기한 항목). dirty cell replay + 미변경 영역 COW. §579 대로 수·anchor·retention을 memory budget과 warm-hit telemetry로 결정한다. time-loop warm 경로(T16 귀속 16.4s)에 대한 접근 폭을 ablation으로 판정한다.
- T26 — whole-cell scalar bundle 재사용 (DESIGN §474; T16 종료 기록이 병목 후보로 명명). 입력 비트가 모두 동일한 cell의 완성된 scalar bundle 전체 재사용을 dependency fingerprint 조건 아래 ablation한다. 기여 없으면 그 사실을 기록한다.
- T27 — ray-tracing acceleration structure / analytical visibility 재설계 (DESIGN §809 명시 연구 후보). svf march 16.9s(원본 네이티브 ~20s와 거의 동일)를 공격하는 문서 내 유일한 구조적 수단. §809 조건 그대로: 현재 discrete step/reset/zero-padding semantics와의 동치 proof를 먼저 내고, proof가 불가능하면 채택하지 않고 그 사실을 미도달 귀속 근거로 기록한다. T19(기존 step 구조 내 reuse)와 독립.
- T28 — 경미 후보 비교(선택): §716 transport dirty-rectangle/chunk-only + lossless compression·byte shuffle(compression/decompression 시간 포함 identity와 비교), §801 compiler auto-fusion(exact harness로만). E2E가 목표 근처에 도달해 의미가 생길 때만 실행하고, 아니면 NOT_RUN으로 기록한다.
- T29 — 도달 가능성 종합 판정 + 원본 측정 규정 폐쇄. 최종 수치는 sampling 최소(n≥100, warmup≥5, randomized paired, hw/부하 기록 — acceptance_targets.yaml sampling 섹션)로 측정한다. 목표별 판정표(현재 → 카드별 개선폭 → 잔여 gap → 도달 여부)를 WORKLOG_ULTRAFAST.md와 README ledger에 기록하고 non-author review를 받는다. selected-exact 판정은 T24 결과를 전제로 잔여 gap을 compute와 대기로 분리 귀속한다.

에이전트 작업 규칙
- 한 번에 하나의 bounded task. author/oracle-test owner/non-author reviewer 분리. 각 변경에 최소 1개 mutation이 지정 test를 죽이는지 확인한다. 프로토콜은 T17 카드 그대로: hypothesis → exact equivalence argument → counterexample search → independent oracle test → measured ablation.
- 채택/폐기는 오직 측정과 문서 관문으로: 정확성 게이트 전부 통과 + 기본 경로 대비 개선 + memory 목표 비침해. 폐기 시 이유를 아티팩트와 함께 남긴다.
- WORKLOG_ULTRAFAST.md에 task/HEAD/files/commands/evidence/status/failure/rollback/next_command 지속 기록. 실제 inputs·cache·live state·production은 read-only, private raster commit 금지, raw 로그를 /tmp에만 두지 마라.

완료와 중단
- 도달 가능성 판정이 목표별로 확정되고(n≥100 측정 + 독립 review) 그 근거가 기록되면 캠페인을 완료한다. 목표 미달성이 증명된 경우도 이 캠페인의 정상 완료다 — 다만 goal(100% 수용 목표 달성) completed는 아니다.
- 예산 종료 시 best verified commit, 남은 bottleneck의 exclusive-time 귀속, 다음 정확한 명령을 남긴다. budget_limit_is_not_goal_completion. 상태 어휘는 PASS/FAIL/BLOCKED/NOT_RUN/TARGET_MISSED만 사용한다.
