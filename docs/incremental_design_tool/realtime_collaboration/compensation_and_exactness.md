# Compensation, uncertainty, and exactness

## Scientific status is part of the data

Every displayed or exported analysis value has one of:

- `exact`: generated by the qualified exact SOLWEIG path for this workspace revision;
- `qualified_provisional`: generated by a validated fast model inside its declared domain;
- `visual_only`: edit state is current, but thermal values are the last exact field plus non-scientific visual cues;
- `stale_exact`: an older exact result shown for comparison while current analysis is pending.

The status is not cosmetic. It travels in API metadata, storage, telemetry, exports, and UI accessibility text.

## Qualification domain

A compensated model is qualified over a finite domain defined by:

```text
site/cache/model version
edit adapter family and operation type
edit magnitude and count
changed-area and object-density range
solar/time range
meteorological range
surface/building/vegetation context
requested output and spatial resolution
maximum age/distance from exact base revision
```

Outside the domain, it cannot return `qualified_provisional`.

## Error contract

For each qualified fast model, publish validation metrics against fresh exact oracle runs:

- maximum absolute error;
- MAE and RMSE;
- p50/p95/p99 absolute error;
- fraction above product-specific threshold;
- spatial boundary error;
- bias by land-cover/geometry class;
- multi-edit and cross-family composition error;
- error growth across several fast revisions since the exact base.

The online payload exposes a conservative error band or qualification class derived from these results. Do not fabricate a per-pixel confidence interval unless it has empirical calibration.

## Exact-base drift

Fast deltas accumulate relative to an exact base. Limit drift by:

- maximum number of fast epochs since exact reconciliation;
- maximum cumulative changed area or source cost;
- maximum geometry/topology change;
- model-specific residual monitor;
- forced exact reconciliation after threshold or idle period.

If drift threshold is crossed before exact catches up, the system remains collaborative but moves to `visual_only` instead of publishing an unqualified numerical field.

## Error compensation options

Use the least complex method that satisfies measured error and latency:

1. exact cached delta or response table;
2. sparse deterministic response kernel;
3. lower-resolution exact solve plus calibrated spatial correction;
4. local linear/sensitivity model with interaction terms;
5. learned surrogate with strict out-of-domain detection.

All options require the same revision, provenance, and reconciliation protocol.

## UI behavior

- `exact`: solid status and exact revision.
- `qualified_provisional`: distinct badge, error envelope, and “refining” status.
- `visual_only`: no numerical claim for changed cells; show current geometry and pending overlay.
- `stale_exact`: state the older exact revision and age.

The user must be able to inspect which source families caused approximation and which stages/caches were reused.
